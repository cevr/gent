# Drive scripts

The script format `verify:drive` runs (`DriveScript` in `packages/e2e/src/pty-fixture.ts`). [SKILL.md](SKILL.md) says how to run one and what it prints on stdout.

- Steps: `["send", text]`, `["keys", name]` (`enter`, `esc`, `tab`, `up`, `down`, `left`, `backspace`, `ctrl+c`, `ctrl+p` …, the `keys` table in `packages/e2e/src/pty-fixture.ts`), `["waitFor", regex, ms]`, `["settle", ms]` (the screen is quiet that long), `["wait", ms]`, `["resize", cols, rows]`, `["cap", name]`, `["capAll", name]` (with scrollback), `["sh", command, ms]` (30 s unless the step names its ms).
- Assertions read the visible screen once, with no wait: `["expect", regex, rows]` holds on a match, `["expectNot", regex, rows]` on none; `rows` is an optional `[first, last]`, 1-based and inclusive, negative from the bottom (`[-3, -1]` the last three). The regex reads the rows joined by newlines, so a match can cross rows. `["fits", rows]` fails a row the terminal wrapped onto the next one and a row whose last two cells are letters, a word cut at the edge; a border, a number or `…` at the edge passes. `["stable", ms]` fails when the screen changes within `ms`. Wait for the text first: an assertion right after `waitFor` reads a screen still drawing (the status row writes `(anthropic)`, then `(Anthropic)`, 100 ms after `ready`, measured 2026-10-23).
- The script is checked before anything runs. A `waitFor`, `expect` or `expectNot` regex that does not compile, a row 0 in a span, a capture name that is not one file name (`../x`, `a/b`), a `cwd` outside `$RUN` (symlinks resolved), or an `env` that sets a variable of the run (`HOME`, `GENT_DATA_DIR`, `GENT_AUTH_DIRECTORY`, `XDG_CACHE_HOME`, `PATH`, `EVIDENCE` …) fails it with `VerifyFailed` (`step: "script"`). An `--out` inside the checkout under any name is refused (`step: "out"`).
- `sh` runs in the workspace with `gent` on `PATH` as the run's wrapper and `$EVIDENCE` set to `--out`. `gent ctl` there finds the run's server through its data directory. Each `sh` step runs in a process group of its own; the step's end stops the group, so a command it left in the background does not outlive it.
- Each step prints one line on stderr: `ok|miss|FAIL <step> <ms>ms`, then the file a capture saved (named from `--out`), or why the step failed. A failed assertion adds the rows that show why: its rows marked `!` with three rows around them, at most 24. `--print` adds each capture's screen after its line. The last stderr line is `pass <ok>/<steps> · <end> · <out>`. Stdout holds only the result.
- A drive that passes copies its captures to `<out>/passed/`. A drive into the same `--out` that fails prints, before the last line, `diff <name>.txt against the last pass` and that capture's changed rows (`-` the pass, `+` now), compared row by row: a row that moved shows as changed.
