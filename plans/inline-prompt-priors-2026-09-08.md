# One-shot prompt output in the main terminal buffer

Research date: 2026-09-08. Queue this work after the cache work. This note does not report an implemented or tested one-shot mode.

Gent already has a native transcript with rich tool cards. Reuse that path for `gent -p`. Add incremental scrollback output and a completion path that flushes the last rows before exit. A renderer flag and automatic exit alone do not meet the request. [G1, G2, G3]

## What OpenTUI supports

| Option or API                            | Verified behavior                                                                                                                                                                                        |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `screenMode: "alternate-screen"`         | Default. Exit restores the main buffer.                                                                                                                                                                  |
| `screenMode: "main-screen"`              | Owns a reserved main-screen region. The official docs explicitly say this is not an inline renderer.                                                                                                     |
| `screenMode: "split-footer"`             | Owns a footer in the main buffer. `footerHeight` defaults to 12 and is capped by terminal height.                                                                                                        |
| `externalOutputMode: "capture-stdout"`   | Requires split-footer. Queues application `stdout.write` output above the live footer. It does not capture `stderr`.                                                                                     |
| `writeSolidToScrollback(renderer, node)` | Renders a Solid tree into a snapshot. It uses the normal text and styling pipeline. The tree is disposed after the snapshot is queued.                                                                   |
| `createScrollbackSurface()`              | Keeps an offscreen render tree. `render()` lays it out. `settle()` also waits for pending code highlighting. `commitRows()` queues selected rows. Geometry changes require a new render before a commit. |
| `clearOnShutdown: false`                 | Keeps the owned main-screen region. Terminal modes still reset. `destroy()` flushes queued output, but does not first turn the live tree into scrollback.                                                |
| `exitOnCtrlC` / `exitSignals`            | These are separate input and signal paths. Gent owns shutdown. Use `exitOnCtrlC: false` and an explicit signal policy that does not race Gent's finalizers.                                              |

Sources: [official renderer guide](https://opentui.com/docs/core-concepts/renderer/), [official lifecycle guide](https://opentui.com/docs/core-concepts/lifecycle/), [renderer source](https://github.com/anomalyco/opentui/blob/6b9863ea7c5fae22bfebb23c242ddcc4c2b0aa0e/packages/core/src/renderer.ts#L153), [Solid snapshot writer](https://github.com/anomalyco/opentui/blob/6b9863ea7c5fae22bfebb23c242ddcc4c2b0aa0e/packages/solid/src/scrollback.ts#L145), and [native shutdown](https://github.com/anomalyco/opentui/blob/6b9863ea7c5fae22bfebb23c242ddcc4c2b0aa0e/packages/native/src/renderer.zig#L583). Local receipts: [O1, O2, O3].

The official [streaming example](https://github.com/anomalyco/opentui/blob/6b9863ea7c5fae22bfebb23c242ddcc4c2b0aa0e/packages/examples/src/split-footer-streaming-demo.ts#L555) commits text/code rows except the last row. For Markdown it commits `_stableBlockCount` entries from `_blockStates`. It then flushes all remaining rows on completion. Those underscore fields couple the example to Markdown internals. The parser retains trailing unstable tokens. A single long unfinished paragraph, table, or code block needs a separate acceptance case; this example alone does not prove that case. [O4, O5]

## Gent behavior and gaps

1. `main.tsx` labels `-p` as an initial TUI prompt. It starts the renderer with no screen mode. `Session` mounts `NativeTranscript`, which switches to split-footer and disables mouse tracking. `main.tsx` then waits for renderer destruction. There is no one-shot completion path. Start the one-shot renderer in its intended mode to avoid a startup buffer switch. [G1, G2, G3]
2. `NativeTranscript` passes the same `MessageList` tree to `writeSolidToScrollback`. Tool cards resolve through the extension renderer registry. Composer approvals use the extension interaction renderer registry. These components can stay in use. They do not require the plain headless renderer. [G2, G3, G6, G7]
3. The native commit effect returns while `props.streaming` is true. At idle, it commits only rows that overflow the live viewport. A long streaming answer can hide earlier rows in its scrollbox until idle. The final screen remains live. One-shot needs both incremental commits during streaming and a final flush of every uncommitted row. [G3:216-273]
4. On mount, the transcript resets the main screen. On width, height, or disclosure change, it can reset with `clearSavedLines: true`. OpenTUI implements that call with screen clearing and optional `CSI 3 J`. One-shot must preserve shell output before launch. It must not call this replay reset or erase saved lines to resize or expand cards. The existing resize patch also affects the clear region, so test the installed bundle. [G3:139-198, G5, O1:2446-2473]
5. Ctrl+O cycles disclosure. Ctrl+Shift+O opens the transcript view. These keys work only while Gent owns input. Committed terminal rows have no live controls. For one-shot, keep live-card disclosure or a temporary inspection view. Preserve complete tool output in session storage for `gent -s`. After exit, the terminal owns scroll and text selection. Do not promise expansion of old terminal rows. [G3, G6, G8:610-644]
6. Initial prompt submission waits for auth and feed readiness. The feed rebuilds state from a snapshot and replay. Completion must track this invocation, not initial idle state, any replayed `TurnCompleted`, or a model `StreamEnded` between tool steps. Supply one stable request ID. The runtime maps it to `message:<requestId>` and waits for that message's turn receipt. Keep that mapping behind its owning API. [G9:486-525, G10:456-506, G11:649-710]
7. `TurnCompleted` has `messageId`, `interrupted`, and `streamFailed`. It is delivered before `turn.after` hooks finish. `Agent.start` can return while a child still runs. Child completion first queues a waking parent follow-up, then emits `AgentRunSucceeded`. Thus the first parent receipt, an empty child card list, or a zero pending-child count is insufficient to prove all owned work has ended. The child card tracker also ignores starts without `toolCallId`. [G12, G13, G14, G15, G16, G17]
8. The headless runner auto-approves `InteractionPresented`. It resolves its completion deferred on `ErrorOccurred` and on any `TurnCompleted`. It does not read the interruption/failure fields there. The CLI also maps interruption-only teardown to exit 0. One-shot must define its own terminal result while it uses the interactive approval path. [G1:726-756, G18:102-124]

## Smallest coherent change

Keep this as a TUI execution mode. Keep the session feed, tool renderer registry, interaction registry, and generic one-cell core. The first changes belong in CLI lifecycle, the session controller/feed boundary, and `NativeTranscript`.

- Start one-shot with split-footer, captured stdout, and `clearOnShutdown: false`. Retain the current approval composer while work runs. Validate conflicting `-H`/`-p` arguments and non-TTY behavior explicitly; neither case may silently inherit headless auto-approval.
- Give the transcript a completion operation. It must wait for the final projected content and layout, commit all remaining rows exactly once, remove the live status/input region, and return the cursor below the answer. Then destroy the renderer and let the Effect scope release services. Do not call `process.exit()` inside a component. [G1, G19, O1, O3]
- Commit an immutable display prefix while output streams. Keep changing text and active cards in the live tail. Use source/block identity, not old row offsets, across resize. Reuse current cards when they become final. A stable-Markdown-block approach still needs a rule for a long unclosed block. Do not hide that gap behind a final flush or a plain-text headless fallback. [G3, G6, O4, O5]
- Preserve previously committed rows across disclosure and resize. Relayout the live tail. Inspect old cards through retained session data. Do not replay the whole terminal buffer. This requires a different ownership rule from the current transcript replay code. [G3, O1]
- Finish only after the owned prompt has a terminal receipt and its follow-up work has settled. Include pending interactions, child completion delivery, and parent follow-up turns. Add a small generic server completion projection only if existing durable receipts cannot prove this condition. A UI timer or activity label cannot prove it. [G10-G17]
- Return 0 for normal completion. Return nonzero for a terminal provider/harness failure. Use 130 for user cancellation as the proposed CLI contract. A recovered tool failure alone need not fail the command. Cancel owned active work before teardown; test connected-server behavior separately because closing a client is not a server cancellation request. [G1, G8, G12, G18]

## Required acceptance

Use deterministic `LanguageModelLayers.signal` streams for lifecycle tests. Keep a real PTY/Herdr check for terminal ownership and scrollback. Existing tests cover native mouse mode, feed/auth behavior, headless exit, and Herdr release. They do not prove this one-shot contract. Upstream tests cover queued-output flush, no-clear shutdown, snapshot cleanup, Markdown blocks, and geometry invalidation. [G20-G25, O6-O8]

1. Put unique shell markers above and immediately before the command. Run `gent -p` in a Herdr pane. After completion, verify exit 0, all markers, the complete answer, final tool cards, a visible cursor, normal shell typing, native wheel scroll, and text selection. Capture terminal bytes to reject `CSI 3 J` and unexpected alternate-screen entry during the normal one-shot path.
2. Hold the provider open after it emits more than three terminal heights. Verify early answer rows are already in native scrollback before `TurnCompleted`. Repeat with a long single paragraph, unfinished Markdown table/fence, Unicode, and narrow-wide-narrow resize. Reject lost rows, repeated rows, and a full-answer-only-at-exit result.
3. Stream text, then a cell with nested host calls, then more text. Open the same card details while work is active. Verify final order and details. Present an approval and a question. Verify Gent waits for input and honors both approval and rejection. No automatic approval is allowed.
4. Start a child that finishes after the parent's first turn. Verify its completion follow-up and the parent's resulting answer are shown before exit. Repeat across server restart and feed reconnect. Replay must not resend the prompt or trigger early exit. Do not use the old child-card tracker as the sole completion check.
5. Test provider failure, request failure, cancellation during text, cancellation during an approval, and cancellation with an active child. Check the intended exit code and retained partial output. Run with both an owned server and `--connect`. Verify storage/locks close and Herdr releases the pane report.
6. Test short output, output exactly at a row boundary, an empty final answer, final code highlighting, and completion while an inspection view is open. Verify the final live rows appear once and the shell prompt starts below them. Then run the full gate and the focused TUI/PTY suite.

These are proposed checks. This research ran no product test, model request, or live terminal experiment.
