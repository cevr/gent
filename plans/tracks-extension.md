# Tracks extension — design

Date: 2026-10-10. Author: Claude, from source read at gent `191b9c4c5` and dotfiles `b1ce469` (baton).
Status: proposed. G1, G2 and G3's catalog check are done (`ca5e999d4`); the release (G8) is deferred by the owner (2026-10-10).

## Goal

The owner's multi-agent improvement loops (the `orchestrate` and `architecture-loop` skills) run today as tracks through baton: a SQLite event log folded into `{ view, messages }`, which drives herdr panes running Claude Code (implementor) and Codex (reviewer, verifier). gent becomes their long-term home. A `@gent/tracks` extension holds the same log and the same fold. Its seats are child sessions of the orchestrator's session, so delivery, wake, cost and resume use gent's durable actors, not terminal panes. baton keeps driving runs until each stage below replaces part of it, and the last stage retires it. Routing becomes code: verdicts, failure caps, the gate queue, cleanup and delivery. Judgment stays with the models: specs, reviews, merges and re-plans.

### Where it lives

`packages/extensions/src/tracks.ts` is one file (owner rule: single files), with section banners: protocol (events), fold, decide, storage, delivery, tools, hooks, extension. Tests go in `packages/extensions/tests/tracks.test.ts`: the fold and decide as pure-reducer tests (ported from `baton/tests/domain.test.ts`), plus one `createRpcHarness` acceptance that drives open → changes → accepted on `LanguageModelLayers.sequence`.

The extension is opt-in, as `@gent/guard` is (`guard.ts:15-18`). It registers nothing until a config file holds a `tracks` entry.

**The log.** It is an extension-owned table, `track_events(run TEXT, seq INTEGER, at INTEGER, event_json TEXT, PRIMARY KEY(run, seq))`, created by a process Resource in the way `background_bash_jobs` is created. Every command is one SqlClient transaction: read the run, `decide`, append. This is the same contract as baton's `Journal.write`. After each append, the extension publishes `ExtensionStateChanged` on the orchestrator's branch, so a TUI widget can refetch.

### Events: baton's, ported

baton's domain is the same Effect v4 dialect (`Schema.TaggedUnion`, `Result`, `Option`), so `event.ts` (65 lines), `state.ts` (417) and `decide.ts` (173) lift nearly verbatim into the fold and decide sections. Three edits are needed:

- `Agent { name, pane }` becomes `Seat { sessionId, branchId, model, effort }`.
- `seatOf` matches the calling session instead of a pane.
- The herdr parts go: `observe`, `blockedSince`, the 32-character `NAME_LIMIT`, and the dialog stall.

### Seats

A seat is a child session of the orchestrator. It is created durable-once with `ctx.Session.create({ cwd, admission: { agent }, modelId, reasoningLevel, requestId: "tracks:<run>:<unit>:<role>" })` (`core/src/domain/extension.ts:1114-1127`).

tracks owns its children and does not use `delegate.start`. A delegate child is shaped as a one-shot task: it ends its turn and reports, and every turn end becomes a completion message to the parent (`delegate.ts:732-750`). A seat lives for the whole track and reports only by passing.

| Seat        | Agent (registered by tracks) | Default model                                                                 | Tools                                                              |
| ----------- | ---------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| implementor | `track-impl`                 | `anthropic/claude-opus-*`, medium                                             | all tools except `track.open/tell/close/integrate`                 |
| reviewer    | `track-rev`                  | `openai/gpt-6.1-sol`, high, through the ChatGPT sign-in (`openai.ts:204-212`) | also denies `write` and `edit`; `paths` is limited to the unit dir |
| verifier    | `track-ver`                  | same as the reviewer                                                          | same as the reviewer                                               |

`agents.track-rev` (and the others) in `.gent/config.json` reshape each default, as an agent patch does (`core/src/domain/agent.ts:527-541`). This replaces baton's `--impl-model`/`--rev-model` flags.

Each agent's `systemPromptAddendum` sends the seat to read `protocol.md` and `safety.md` in full. That replaces the orchestrate mod's safety injection.

`track.open` refuses an implementor and a reviewer from the same provider family unless the call says `sameFamily: true` (need 9). Seats show up in the agents view for free (`agents-view.ts`).

### Pass, ask and tell

| baton                           | tracks                                             | Mechanism                                                                                                                                       |
| ------------------------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `baton open <unit> --cwd`       | `track.open {unit, cwd, verifier?, maxFailures?}`  | Orchestrator only. It creates the seats, appends `TrackOpened`, and delivers the kickoff.                                                       |
| `baton pass <file> [--verdict]` | `track.pass {file, verdict?}`                      | A seat tool. It is refused to a seat that does not hold the baton (`decide.holds`). For the implementor it reads `git -C <cwd> rev-parse HEAD`. |
| `baton ask` / `baton tell`      | `track.ask {file}` / `track.tell {unit, to, text}` | Verbatim decide.                                                                                                                                |
| `baton close [--merged]`        | `track.close {unit, merged?}`                      | It deletes the seats, then does the cleanup (need 4).                                                                                           |
| `baton status` / `whoami`       | `track.status` (a tool and a request)              | The goal comes first, then each track's holder, step and round, and the cost per round.                                                         |
| `baton redeliver`               | none                                               | A reconcile on `loopOpen` sends every owed message again, as delegate's reconcile does (`delegate.ts:814-975`).                                 |
| `baton tick` / `watch`          | none                                               | Nothing polls. See the seat hook below.                                                                                                         |

**Delivery.** Each message the fold owes becomes `ctx.Session.send({ delivery: "queue", sessionId, branchId, sourceId: "tracks:<run>:<ref>", wake: true, content })`, followed by `MessageDelivered{ref}`. If the process crashes between the two, the next send is a no-op (`core/src/domain/extension.ts:994-996`). The orchestrator is woken the same way, because it is just another session.

**Seat hook.** On `turnAfter` (`TurnAfterInput`, `core/src/domain/extension.ts:519-573`) for a seat session, tracks appends `SeatTurnEnded`. If the seat holds the baton and the turn ended with no pass or ask:

- A usage limit is already re-armed by wake's auto-resume.
- An interrupt goes to the orchestrator.
- Any other end gets one nudge ("pass your file with track.pass"). A second unpassed end becomes `StallDetected{unpassed}`.

## Stages

1. **One track, end to end.** Build `tracks.ts` with the log, the lifted fold and decide for implementor and reviewer only, `track.open/pass/ask/tell/close/status`, queue delivery, the seat hook, and the reconcile on `loopOpen`. The orchestrator makes the workspace itself and passes `cwd`, as with baton. There is no gate queue, no integrate step and no verifier. G1, G2 and G3 are in; run from a `dev-<hash>` build (G8). **Done when** the RPC acceptance passes, and one real small unit runs open → at least 2 rounds → accepted → merged by hand → closed, with every step in `track_events`. A server restart mid-round must lose no message.
2. **The gate and integration.** Ship G4, G5, G6 and G7, plus `baton gate`. **Done when** three parallel tracks on the workbox serialize their gates with queue receipts, each merges through `track.integrate`, its branch and workspace are gone after close, and `track.status` shows the cost and compactions per round.
3. **Verifier, pause and resume.** Add the verifier seat, `track.pause` and `track.resume`, and a client widget for `/tracks`. **Done when** a run paused mid-round on the Mac resumes on the workbox from its bundles and its log alone, with the goal intact.
4. **The loop on tracks.** Move the ledger to events (need 7), and rewrite the `orchestrate` and `architecture-loop` skills to use the tracks tools. **Done when** one full architecture-loop pass on gent runs with no baton call.
5. **Retire baton.** Remove `baton/`, the orchestrate mod's baton guard and watchdog, and the dotfiles hook that builds baton. The gate lock stays wherever stage 2 put it. **Done when** no skill or mod names baton.
