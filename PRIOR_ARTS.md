## Settled

- Line counts across these repos compare different scopes (one file against gent's whole loop). Draw no size conclusion from them.
- gent's step policy (`classifyStep` in `packages/core/src/runtime/turn.ts`, a pure function with a table test) already matches opencode v2: adopted.
- The queue-as-one-module shape (opencode `inbox.ts`, codex `input_queue.rs`) is adopted: `packages/core/src/runtime/agent-loop.ts`.
- fx's settle-then-capture pty method is adopted: `packages/e2e/src/pty-fixture.ts`.
- The inspected prior-art paths do not persist gent's step-position and in-flight execution receipt contract. Pi 1.0 persists tool/prompt deltas and virtual-model state; those do not supply that contract. gent's exact mid-turn resume (in `packages/core/src/runtime/agent-loop.ts` and `packages/core/src/runtime/turn.ts`) is a capability the owner keeps or drops; a sweep does not decide it.
- The yield of every comparison so far was bugs found while reading gent with the prior art in mind, more than code removed.
- Rejected from prior art: an LLM permission reviewer, a static tool table, a mutex event queue, unbounded steps, whole-log replay, text-blob compaction (`NORTH_STAR.md` → Rejected).
- Pi main 1.0 (`86dfceec4`, Pass 27) replaces the historical pico comparison. gent already has kernel tool discovery, MCP calls and classifiers; a second tool-exposure vocabulary or codemode sandbox is not adopted. Physical routing/accounting and persisted prompt/tool deltas are capability gaps, with no measured saving claimed.
- Pi's warmer makes paid replay requests, bounded by lifetime, replay safety and expected savings. gent retains its one-hour root/five-minute child caches and cold-window handoff. Unconditional idle pings remain rejected; an opt-in warmer needs matched task cost and quality evidence.
- A native image-model primitive has no current consumer. Pass28's full extension review and root's product-source search found no image-generation caller; existing image handling projects message/MCP content. Decided by small-interface-deep-implementation and subtract-before-you-add: keep image generation in an ordinary extension tool if requested, and add a kernel primitive only for a demonstrated need.
- PI27-4 prompt/tool deltas (Pass 28, `~/.cache/architecture-loop/gent/pass28/efficiency.md`): no core stable/changing agent-block split. Shipped extensions and real sessions keep the agent block byte-stable (saving 0). When an extension changes content mid-session, the existing `notices` path costs less than a split on every replayed capture (38.9–65.4% against 27.8–60%), with no core change. The extension guide now says so (EF28-1). Pi 1.0 native transcript deltas stay out of scope.
- PI27-1 virtual models, owner decision (Pass 28): gent keeps explicit model selection (`/model`, `agents[name]`, `driverOverrides`, RunSpec overrides). There is no core routing seam and no automatic or per-turn router. A later routing policy is an opt-in extension. It needs matched completed-task cost and quality evidence, and physical-model prices, limits, admission and accounting stay authoritative. Pass 29 rechecked Pi `c10bfb0d7` (`virtual-models.ts` unchanged since Pass 27) and found no new evidence. Reopen only on an owner request or a paid matched measurement the owner authorizes.
- PI27-3 cache warming, owner decision (Pass 28): no warmer. gent keeps the Anthropic root 1-hour and child 5-minute cache lifetimes, the shared-block markers and the cold-window handoff. The loop sends no keep-alive. If the owner authorizes a paid matched measurement, the first candidate is streaming-only warming. Idle pings stay rejected. Pi's 0.15 idle probability and $0.05 threshold are Pi's policy, not gent evidence. Pass 29 rechecked Pi `c10bfb0d7` (`cache-warmer.ts` unchanged since Pass 27) and found no new evidence. Pass 30 measured it (`~/.cache/architecture-loop/gent/pass30/research-cache-ttl.md`; Pi `9fba660cf`, `cache-warmer.ts` unchanged): on 87,440 recorded Claude Code requests the 1-hour lifetime costs least; 5-minute options cost 7–30% more and raise cold compaction from 3.7% to 26% of turn starts; a child streaming warmer would save 2.7–9.2% but needs a core replay verb. Owner decision (2026-10-03): keep the 1-hour root cache, no warmer, no mixed lifetime.
- Pi `c10bfb0d7` (Pass 29, `~/.cache/architecture-loop/gent/pass29/prior-pi1.md`): Anthropic inline tool definitions (`inline-tools-2026-09-15`) do not reopen PI27-4. gent's tool list stays fixed per session, and changing extension content goes through `notices`. MCP CIMD client registration needs a hosted https client document, which gent does not have, so dynamic registration stays. gent's retry reads typed errors and the event shapes each driver names, never message text, so pi's text patterns are not adopted.
- opencode v2 `1549712761` (Pass 29, `~/.cache/architecture-loop/gent/pass29/prior-opencode.md`): 308 commits since the Pass 22 ref `5c53cfc342`. The step outcome, the inbox and the hook surface did not change shape, and the Settled rows above hold. Open from this comparison: a provider refusal handled as a block, not as an empty answer (P29-1); a cache group for spawned sessions (P29-2, EF24-Q1, measure first); text verbosity (P29-3: owner decided low, sent since `ec5157a19`). Rejected: eager tool start (breaks binding-before-run, rule 6), native provider compaction (an opaque window tied to one endpoint, against rule 17; no measured saving), saved permission rules (rule 7).
- prime-agent is a Rust parity port of its TS product since `39bc99a` (2026-09-29), so the TS paths earlier passes cite are gone. At Pass 29 (`cf285dc`) its loop is still pi's shape, it still has one model tool (`ipython`), and a child still reports by message; `rlm.collect` with timeout 0 is the snapshot `delegate.list` already gives (A3 stays rejected). Not adopted, with no consumer: ACP, `rlm.create_session`, progress notes, the continual harness, the agent-message rate limit, and dropping the turn cap. Taken from it: process-group reaping after a host crash (P29-prime-1, -3) and a headless run that waits for its children (P29-prime-2). Report: `~/.cache/architecture-loop/gent/pass29/prior-prime.md`.
- t3code `0c811201` (Pass 30, `~/.cache/architecture-loop/gent/pass30/prior-t3code.md`): orchestration V2 is an event-sourced command processor over external agent CLIs (Codex, Claude Code, Cursor, ACP, OpenCode, Pi). It has a per-thread semaphore, one transaction for events, projections, receipt and outbox, and a worker pool for provider I/O. gent already has the overlap (durable idempotent commands, rule 5, cursor replay, children that wake the parent) in a stronger form: one actor mailbox per branch, and no lock-order or commit-publish races (t3code `6108ef3d`, `5108c978`). Not adopted, with no consumer because gent owns its loop and transcript: run attempts, steer by restart, capability flags, provider rollback and portable provider handoffs. Rejected: `delegate_task` `mode: wait` (children wake, never block), retry by error text, `completionWake` policies. Open owner questions: per-turn workspace checkpoints with `/diff` and `/revert` over `branch.fork` (O1), worktrees for children (O1b), `/btw` merge-back (O2), resume at a usage-limit reset (O3), gent as an ACP agent (O4).
- opencode's models.dev catalog (`dev` `c42ae0d56b`, Pass 30, `~/.cache/architecture-loop/gent/pass30/proposal-models-dev-catalog.md`): adopted — models.dev fills one core catalog, a model's npm package and protocol pick its API class, a key env variable or a stored key activates a provider, and config adds or patches providers (`packages/core/src/runtime/provider.ts`). Not adopted: the bundled snapshot (owner decision: no snapshot in the binary), the five-minute full refetch (gent revalidates hourly with an ETag) and the file lock (SQLite serializes the writers of `model_catalog_snapshots`).
